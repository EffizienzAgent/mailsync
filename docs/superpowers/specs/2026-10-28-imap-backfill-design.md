# IMAP backfill: one-off import of past mail

Status: draft for review (2026-10-28)

## Intent

Tobi keeps customer mail in IMAP mailboxes that are not polled by the CRM, among them private mailboxes with customer subfolders. He wants a one-off import of that history into Frappe Communications, linked to the right contacts and companies.

The import is also a tool to complete the address book. Many addresses in old mail belong to people the CRM does not know yet, or to known people whose second address is missing. The import shows these addresses and lets him create a contact, add the address to an existing contact, or ignore it. A mail is only worth importing if at least one person in it is someone he wants in the CRM.

Mail often involves several companies (a customer and the customer's partners). Every involved contact and its companies get the link, not one "folder company".

## Goals

- Import past mail from chosen folders of an IMAP Email Account within a date range, as Closed Communications.
- Before importing, list the addresses the site does not know and let the user decide per address: new Contact, add to existing Contact, or ignore.
- Import only mails in which at least one known Contact is involved (after the decisions).
- Link through the normal Frappe path: addresses → Contacts → the Contact's Dynamic Links.
- Idempotent: re-running over the same range never creates duplicates.
- Handle large folders: batched background jobs that resume, with progress and a result summary.
- Works without any other app. CRM-specific knowledge comes in through hooks.

## Non-goals

- Upload of `.mbox` / `.eml` files. Later, if someone asks for it. Keep the import pipeline separable from the IMAP fetch so it can be added.
- Microsoft 365 / Gmail APIs.
- Continuous sync of the imported mailbox.
- Mapping folders to companies. The folder plays no role in linking.

## Anti-goals

- Writing to the mailbox in any way: no move, flag (including `\Seen`), delete, append or send.
- A backfill mailbox ending up polled by `sync_all` or Frappe's stock pull.
- Private or unrelated mail entering the CRM because nobody decided about its addresses.
- The import creating Contacts on its own, for example through Frappe's *Create Contact* setting on the Email Account.
- Inbox noise: imported mail must not show up as open or unread, trigger notifications, auto-replies or assignment rules.
- CRM concepts (Organization, Organization Email Domain) inside mailsync.

## Decided

### Access and credentials

- The import uses a normal Email Account. A mailbox meant only for imports is an Email Account with *Enable Incoming* turned off. Frappe and mailsync only poll accounts with *Enable Incoming* on, so it is never polled, but host, login and password stay stored. (Frappe hides the IMAP tab when *Enable Incoming* is off: set the account up with it on, so Frappe checks the connection and folders, then turn it off. Document this in the README.)
- Accounts with *Enable Incoming* on can be imported from too.
- Only the users the account is assigned to (the User's *User Emails* table) and System Managers can create, see and run imports for an account.
- mailsync stores no credentials of its own.

### The import record

A new DocType in mailsync (working name *Mail Import*), one record per run:

- Email Account, folders chosen from the server's folder list (IMAP `LIST`, including subfolders), date from / to.
- Status: Draft → Scanning → Review → Importing → Done (plus Failed). Counters and a summary: imported, already present, filtered out (no known contact), skipped (too large), failed.

### Scan

- Background job, batched, resumes after a timeout or restart where it stopped.
- Reads headers only, without setting `\Seen` (`BODY.PEEK`, folders selected read-only).
- Records per mail what the review and import need: folder, UIDVALIDITY, UID, Message-ID, date, subject, From/To/Cc addresses, size.
- Mails whose Message-ID is already a Communication, is in the Email Queue or was generated by the site are marked as already present (same rule as the Sent folder import, `SentMail.is_known`).

### Review

- A list of addresses in the scanned mails that are not known, with the display name from the headers, the number of mails and some sample subjects.
- "Known" without hooks: the address is a Contact Email of some Contact. Own addresses never show up (see hooks).
- Per address: create a new Contact (name prefilled from the header), add the address to an existing Contact, or ignore.
- Ignored addresses are remembered site-wide and stay ignored in later scans and imports. Ignoring applies only to the import; the regular mail flow is untouched (Claude's call).
- A new Contact can be linked to a company: a Dynamic Link (link doctype + name) on the Contact. Without hooks the user picks the doctype freely (for example Customer). With the company hook the doctype is fixed (Organization in the CRM) and a suggestion is prefilled. Creating a company uses Frappe's normal "Create new" from the link field, so mailsync never needs to know the company doctype (Claude's call).

### Import

- Can be started at any time, also before the review is finished.
- A mail is imported when at least one non-own address in From/To/Cc is a Contact. Mails whose only other participants are ignored are filtered out. Mails that still have undecided addresses and no known contact stay pending in the record and are picked up by the next "Import" run once their addresses are decided (Claude's call; Tobi did not object).
- Fetches the full mail with `BODY.PEEK[]`. Respects the 25 MB per mail limit (skipped and counted) and per-run limits like the Sent folder import (count and bytes per batch).
- Creates a Communication with status Closed, seen, `sent_or_received` Sent when the sender is an own address, otherwise Received. Re-checks the Message-ID right before insert.
- Linking goes through Frappe's normal timeline linking (Contacts and their Dynamic Links). The import never auto-creates contacts, whatever the Email Account's *Create Contact* says.
- Links are set once, when a mail is imported. A decision made later does not re-link mails that were already imported or already present (Tobi's decision).
- Runs the existing `mailsync_mail_read` hook for each imported mail (so an archive app like docarchive keeps the original `.eml`), with the right `sent_or_received`.
- Running the same import again, or a new import over an overlapping range, imports nothing twice.

### Hooks (extension points for the CRM)

mailsync works fully without them. This design covers mailsync only. inocea_hub implements the hooks in its own work after the mailsync release (Tobi's decision), building on its existing logic (`inocea_hub/own_addresses.py`, `inocea_hub/mail_hooks.py`, Organization Email Address / Organization Email Domain). Same conventions as the existing hooks: list of dotted paths, untrusted string arguments, errors logged and the import goes on.

- **Own addresses**: is this address one of ours? Default without hook: email ids of all Email Accounts and of enabled system users. inocea_hub: `belongs_to_own`. Own addresses are left out of the review and decide the direction.
- **Company doctype**: which doctype a new Contact is linked to as its company. Without hook: the user chooses.
- **Suggestions for an address**: a suggested company (`link_name` of the company doctype) and optionally a suggested existing Contact.
- **Links on imported mails**: the existing `mailsync_recipient_links` hook, called for the participants of imported mails as well, so the CRM can add Organization links the way it does for Sent mail.

A domain match (Organization Email Domain) only gives a suggestion. A mail still needs a Contact to be imported.

## Left to the builder

- DocType names, field layout and how mails and addresses of a run are stored (a run can hold tens of thousands of mails, so likely separate DocTypes rather than child tables).
- The UI for the review list (list view with actions, a Frappe page, or a dialog), as long as many addresses can be handled quickly.
- Batch sizes, job timeouts, the job name scheme, and how scan and import coexist with `sync_account` on a polled account.
- `SINCE`/`BEFORE` versus `SENTSINCE`/`SENTBEFORE` for the date range.
- How the importer marks its Communications so other apps can skip notifications (for example a flag on the document).
- Exact hook names and signatures, documented in the README like the existing ones.
- How UIDVALIDITY changes between scan and import are handled (rescan the folder is fine).
- Translations (German, `translations/de.csv`).
